What the code does

  1. 1. Hear the request adaptive.py
    on_caller()

    Keep recent speech. Recognize a practice request and start background planning.

  2. 2. Generate scene data reasoner.py
    GuavaPlanner.decide()

    Guava’s LLM helper returns a Decision: operation, character, situation and activity.

  3. 3. Check and apply adaptive_models.py
    adaptive.py · _apply()

    Validate the data’s structure and current request. Discard plans cancelled by pause or end.

  4. 4. Change the live call set_persona()
    add_info()
    set_task()

    Set the role and voice, supply scene context, then run the activity.

Data, not generated Python. The model describes the scene. Our existing code validates and runs it. Guava handles ordinary spoken replies without a new planning request.

“Hey coach” takes a shortcut: save the exchange → cancel older plans → restore Mira’s role and voice. No planning wait is needed for that pause.

Different conversations, same code

  • Manager → workloadLet’s rehearse asking my manager to move a deadline.
  • Roommate → boundariesLet’s practise asking my roommate to be quieter at night.
  • Friend → borrowed gearLet’s rehearse asking my friend to return my gear by Friday.

There is no boyfriend-specific template. The caller’s story supplies the role, behaviour and goal. These are example requests, not a fixed menu.

The current prototype uses one voice for Mira and one alternate voice for all fictional characters. Personality changes do not create or clone a new voice.

“Change the character” → adjust · 1 from coach → replay · 9 → end · * → help

Recent context, not unlimited memory. Fictional practice, not licensed therapy.
